# AGENTS.md — Repository Control Rules

This repository is a teacher's personal database for teaching, school operations, and workload management. These rules control how an AI assistant works with the repository.

## Before starting
1. Read this file.
2. Read [PROJECT.md](PROJECT.md) to understand the database and find the relevant records.
3. Read only the source files needed for the task.
4. If the request or the correct source is unclear, ask before making changes.

## Permission and change control
**Ask the repository owner for confirmation before:**
- adding any file, folder, or new record;
- deleting a file or folder, or removing existing content;
- renaming or moving files or folders;
- making a bulk edit or changing the repository structure;
- changing an approved timetable or another established school arrangement.

Do not treat “organize,” “clean up,” or “improve” as permission to add, delete, remove, move, or rewrite content. Explain the proposed change and wait for confirmation first. For other tasks, make only the changes clearly requested.

## Keep the database reliable
- Check [PROJECT.md](PROJECT.md) to find the right place for each kind of information.
- Prefer the existing source of truth. Link to it instead of copying the same information into multiple places.
- Preserve existing information and its meaning. Do not silently replace a record with a guess or an assumption.
- Keep the main timetable separate from the temporary 60-minute timetable.
- Do not present a timetable proposal as approved, a component list as confirmed stock, a project idea as completed work, or a planned lesson as a lesson already taught.
- Use full class-section names such as `Class-5-C` and `Class-5-D`.
- This repository is public. Do not add identifiable student information or private staff information.

## Check and report
Before finishing, check the edited content, affected links, dates, durations, calculations, and related records where relevant. Do not change unrelated files. State what changed, what you checked, and anything that remains uncertain. Never claim an edit or verification succeeded unless it did.

## Keep these files separate
- **AGENTS.md:** rules for how an assistant handles this repository.
- **PROJECT.md:** the purpose of the teacher's database, its organization, and where information belongs.

Keep this file limited to repository permissions, editing standards, verification, and reporting.
