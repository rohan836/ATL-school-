# AGENTS.md — Repository Control Rules

These instructions govern how an AI assistant works with this repository. They are intended to remain stable as the database grows.

## Start here
1. Read this file.
2. Read [PROJECT.md](PROJECT.md) for the database's purpose and operating model.
3. Use [INDEX.md](INDEX.md) to discover current records and locations.
4. Read the relevant source records before answering or editing.

If the request, source of truth, or intended change is unclear, ask a focused question before acting.

## Permission and change control
Ask the repository owner for confirmation before:
- adding a file, folder, or record;
- deleting a file or folder, or removing existing content;
- renaming or moving files or folders;
- making a bulk edit or changing the repository structure;
- changing an established or approved arrangement.

A direct request that explicitly names the record or change authorizes that specific action. It does not authorize unrelated additions, structural changes, or destructive actions. Do not treat “organize,” “clean up,” or “improve” as blanket permission. Explain a proposed change and wait for confirmation when permission is not clear.

## Preserve database integrity
- Treat repository records as the source of truth; distinguish facts, plans, decisions, ideas, actions, and historical records.
- Search for relevant records before creating or updating one. Prefer linking to an existing source over duplicating its contents.
- Preserve meaning and provenance. Do not silently replace missing information with guesses or assumptions.
- Do not state that something is approved, completed, tested, available, assigned, or agreed unless a record supports that status.
- Keep private or identifying information out of this public repository. When in doubt, ask before recording sensitive details.
- Use the repository's applicable domain guidance and templates, when present. Do not assume every future database area follows today's categories.

## Verify and report
Before finishing:
- check the edited content and relevant links;
- verify dates, calculations, and connected records when relevant;
- avoid unrelated edits;
- report what changed, what was checked, and any uncertainty.

Never claim an edit or verification succeeded unless it did.

## File responsibilities
- **AGENTS.md:** stable rules for assistant behavior, permissions, preservation, and verification.
- **PROJECT.md:** stable purpose and operating model of the database.
- **INDEX.md:** evolving map of the current repository and its records.
- **Skills:** reusable procedures for common workflows; they do not override these rules or grant permissions.
- **Records:** the actual knowledge, plans, events, decisions, and history stored in the database.

Keep control documents general. Put changing paths, current records, domain-specific conventions, and examples in the index or relevant records.
