# Capture Knowledge

Use this workflow when the owner wants to save new information, a useful idea, a decision, a lesson learned, or other knowledge for later retrieval.

## Procedure
1. Read `AGENTS.md`, `PROJECT.md`, and relevant entries in `INDEX.md`.
2. Identify what kind of information this is: fact, idea, plan, decision, action, result, or historical note. Do not turn one type into another.
3. Search for an existing record on the same subject. Prefer updating or linking that record when appropriate; avoid duplicates.
4. Identify a suitable existing location and record format. If a new file, folder, or record is needed, follow the permission rules in `AGENTS.md`.
5. Capture the useful context: a clear title, date or timeframe when known, source or origin when relevant, status, and related records.
6. Preserve uncertainty. Mark unknown details as unknown rather than filling them with guesses.
7. Update `INDEX.md` if the approved addition changes the navigable structure or introduces an important source.
8. Verify the new or updated record and its links. Report where the information was saved.

## Suggested record elements
Use only what makes sense for the information; this is not a mandatory universal template:
- Title
- Recorded date / relevant date
- Summary or details
- Type and status
- Source / context
- Related records
- Next action, if one exists

Do not force a timetable, project, lesson, or other domain-specific record into an unsuitable generic format.
