# Class 5 — Six-Month AI & Computing Curriculum

**Course:** Foundations of Computing, Python and AI  
**Duration:** 6 months · 12 sessions per month · 72 sessions total  
**Session length:** 60 minutes (use the extension activity if a 75-minute period is available)  
**Level:** Beginner; no coding experience assumed  
**Core approach:** concrete examples → guided practice → small build → test → explain.

## Course goal
Students learn what computers do, how instructions and data work, how to write or modify very small programs, what AI can and cannot do, and how to present a safe, simple project. AI is one part of computing, not a shortcut around understanding.

## Learning outcomes
By the end of the course, a student can:
- Identify common computer parts and explain input → processing → output using familiar examples.
- Use files and folders carefully and follow basic lab, account and privacy rules.
- Describe an algorithm as an ordered set of steps; test and correct a simple sequence.
- Read and modify a small block-based program or beginner Python example.
- Organise simple observations in a table and explain why examples and labels matter.
- Distinguish a fixed rule from an AI prediction; test a prediction and point out a possible error.
- Build and explain a small prototype, including one limitation and one human check.

## Six-month sequence

| Month | Focus | Essential concepts | Student evidence |
|---|---|---|---|
| 1 | Computer and digital foundations | Hardware/software, input-processing-output, peripherals, files/folders, safe lab habits | Labelled computer diagram and organised sample folder |
| 2 | Computational thinking | Sequencing, decomposition, patterns, algorithms, debugging, block-programming logic | Tested step-by-step solution or short block program |
| 3 | First programming steps | Commands, output, variables as named boxes, simple input, sequence and simple conditions | Modified program with a brief explanation |
| 4 | Data in everyday life | Text/numbers/images, tables, categories, counts, simple charts, data quality | Small table/chart and a conclusion based on data |
| 5 | AI fundamentals | Rule-based systems vs learned models, examples, labels, classification, prediction errors | Paper or teacher-guided classification experiment |
| 6 | Capstone and responsible use | Problem definition, prototype, test cases, iteration, privacy, fairness, communication | Demonstration, test record, and reflection |

## Appropriate technical depth
Use blocks or a browser-free Python setup for the main pathway. Python should stay small and readable: `print()`, simple variables, input where appropriate, and elementary `if/else` only after learners understand the logic. Do not require students to train large models, create accounts on public AI tools, use webcams, or install advanced libraries.

## Project pathway
Use age-appropriate, low-risk builds such as a quiz with rules, a classroom helper based on a checklist, a plant-care decision tree, or a paper classifier using fictional examples. A paper simulation must be described as a simulation, not as a trained AI system. See [Project Guides](02-PROJECTS.md).

## Delivery principles
- Make concepts observable: learners predict what an instruction or model will do before running it.
- Teach vocabulary when it helps explain a build; avoid long definition-only lectures.
- Normalise debugging. Students record what they expected, what happened, and what they changed.
- Provide paired work and accessible no-device alternatives.
- Never use student-identifying data in public AI tools. Follow school policy and teacher supervision.
- Check generated or predicted outputs; plausible output is not automatically correct.

## Success standard
A student succeeds by explaining the process, testing at least a few cases, learning from a mistake, and describing limitations—not by producing the most complex app or having the newest device.
