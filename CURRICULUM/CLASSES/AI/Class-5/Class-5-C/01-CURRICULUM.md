# Class 5 — AI Builders: Project-Driven Curriculum

**Status:** Updated project-driven curriculum for planning and review  
**Audience:** Class 5 learners (approximately 10–11 years old)  
**Duration:** 6 months; 3 sessions per week; 12 sessions per monthly project (72 sessions total)  
**Session length:** 60–75 minutes; use the shorter lesson variant when the timetable requires it  
**Approach:** Project-Based Learning (PBL), guided experimentation, computational thinking, and responsible AI  
**Prerequisites:** No prior AI or coding experience. Start with visual tools and teacher-guided activities; introduce text coding when it supports the project.

## Curriculum purpose

Students learn AI by solving meaningful, age-appropriate problems and building interactive prototypes. Each month starts with a challenge, not a lecture or vocabulary chapter. Concepts are introduced when students need them to make, test, or improve their project.

The course progresses through six connected experiences:

**Recognize → Understand image regions → Interact → Generate → Use tools → Design a solution**

This is an instructional curriculum, not a claim that Class 5 students will train production-grade AI systems. Use small datasets, teacher-approved tools, pretrained models where appropriate, and guided simulations. No public student AI accounts are required.

## Six-month overview

| Month | Challenge | Project | Main AI learning | Student outcome |
|---|---|---|---|---|
| 1 | How can we sort waste more consistently? | AI Waste Detective | Image classification, labels, training, prediction, testing | Interactive waste classifier |
| 2 | How can AI highlight the exact region of an object? | Image Segmentation Explorer | Segmentation, pixels, masks, regions | Image tool that displays object masks |
| 3 | Can we control a game with gestures? | Gesture-Controlled Game | Gesture recognition, classification, real-time input | Webcam or simulated gesture game |
| 4 | Can a computer generate a new sentence from learned patterns? | Mini Text Generator | Tokens, sequences, next-token prediction, language models | Small guided text-generation demo |
| 5 | Can an AI system use tools to complete a bounded task? | Classroom AI Agent | Goals, observations, actions, tool use, feedback | Agent using approved classroom tools |
| 6 | Can we build an AI solution for a school need? | AI School Helper | Choosing a technique, integration, evaluation, human oversight | Student-designed prototype and presentation |

## Learning domains and where they appear

| Domain | Concepts and skills | Main project connections |
|---|---|---|
| AI literacy | AI vs ordinary software; model; input/output; training/inference; limitations | All months |
| Machine learning and data | Dataset, labels, examples, training/test separation, prediction, error, simple accuracy | 1, 3, 6 |
| Computer vision | Image classification, object regions, segmentation masks, pixels, gestures | 1, 2, 3 |
| Coding and computational thinking | Sequences, variables, conditions, events, loops, lists, functions, strings, debugging, simple state | 1–6 |
| Language AI | Text patterns, tokens, sequence prediction, generation, output review | 4, 5, 6 |
| Intelligent systems | Goals, observations, actions, tools, feedback, bounded task planning | 5, 6 |
| Mathematics for AI | Counting, categories, patterns, percentages, coordinates, grids, simple probability intuition, graphs | 1–6 |
| Engineering and communication | Define problem, prototype, test, diagnose, iterate, document, demonstrate | 1–6 |
| Responsible AI | Privacy, consent, fairness, representation, misinformation, attribution, human review | All months |

## End-of-course learning outcomes

By the end of the course, students should be able to:

- Describe a simple AI workflow: examples/data → training or model setup → prediction/output → testing → human review.
- Distinguish classification, segmentation, and text generation using a concrete example.
- Explain how data and input conditions can affect a model’s output.
- Test a prototype with new or varied examples and record what happened.
- Identify a limitation or error and propose a specific improvement.
- Use simple coding constructs to modify a guided project.
- Explain what an AI agent is and how a bounded tool-using system differs from a chatbot that only responds.
- Choose whether AI is a sensible approach to a problem; explain one benefit, one risk, and where a person remains responsible.
- Present a working prototype or honest paper/software simulation and describe its limitations.

## Monthly project cycle

Use a repeatable four-week rhythm for each project:

| Week | Focus | Evidence |
|---|---|---|
| 1 | Discover the problem; explore examples; create a first working or simulated version | Problem statement and prototype |
| 2 | Learn the required concept; add a feature; test | Working feature and test notes |
| 3 | Investigate errors; compare inputs/results; improve | Before/after evidence |
| 4 | Finalize; debug; prepare and deliver a demonstration; reflect | Demonstration and reflection |

The 12-session breakdown is in [03 — 72-Session Plan](03-72-SESSION-PLAN.md). Project details and alternatives are in [02 — Project Guides](02-PROJECTS.md).

## Lesson structure

### 75-minute version
- 5 min — Challenge, short demonstration, or question
- 5 min — Student prediction or exploration
- 5–8 min — Just-in-time concept explanation
- 20–25 min — Guided build
- 15–20 min — Student experiment and testing
- 10–12 min — Improve, share, save evidence, or reflect

### 60-minute version
- 5 min — Challenge and prediction
- 5 min — Essential concept
- 20 min — Guided build
- 20 min — Experiment and improve
- 10 min — Share, reflect, and save evidence

Protect hands-on time. Avoid long lectures before students can interact with the project.

## Coding progression

| Concept | Introduce | Reuse |
|---|---|---|
| Sequence and events | Month 1 | All projects |
| Variables and conditions | Month 1 | Classifier, game, agent |
| Lists and simple data structures | Month 2 | Images, gesture examples, datasets |
| Loops | Month 2–3 | Repeated tests and game behavior |
| Functions | Month 3 | Reusable project components |
| Strings and text handling | Month 4 | Text generation and agent responses |
| State and tool calls (guided) | Month 5 | Agent and capstone |
| Integration and debugging | Month 6 | Capstone |

Block-based programming is a valid entry point. Python is an optional progression, not a barrier to participating.

## Mathematics connections

| Mathematics idea | Practical connection |
|---|---|
| Categories and counting | Labels and class examples |
| Patterns | Image, gesture, and text examples |
| Fractions and percentages | Simple accuracy: correct predictions / test examples |
| Coordinates and direction | Gesture-controlled game |
| Grids and pixels | Segmentation masks |
| Sequences and probability intuition | Next-token generation |
| Tables and graphs | Compare test conditions and outcomes |
| Logic and step order | Agent goals, tools, and actions |

Use age-appropriate examples. Do not require advanced algebra, calculus, or formal probability.

## Assessment philosophy

Assess understanding, testing, improvement, teamwork, and explanation—not access to expensive devices or the ability to copy code. A project can be assessed using a prototype, a teacher-guided simulation, or a paper alternative where necessary.

The common rubric, evidence checkpoints, and safety guidance are in [04 — Assessment and Teacher Guide](04-ASSESSMENT-AND-TEACHER-GUIDE.md).

## Access, safety, and implementation boundaries

- Use only school-approved tools and comply with school policies and applicable privacy requirements.
- Do not upload student names, faces, voices, locations, contact details, passwords, school records, or identifiable student work to an AI service.
- Use fictional, teacher-created, or appropriately licensed data. Do not collect sensitive traits or ask students to classify classmates.
- No public student accounts or unrestricted internet access are needed.
- Keep Month 5 agents limited to teacher-approved information and safe tools; require human approval for consequential actions.
- Use pretrained models or guided small-scale demonstrations for segmentation and text generation. Do not promise to train a large model from scratch.
- Provide offline, paper-based, or prepared-data alternatives when connectivity, cameras, or devices are unavailable.
- Hardware is an optional extension, not a prerequisite for the AI learning sequence. Check inventory before promising a build.

## Optional electronics extension

The existing [AI Colour Detective project](02-PROJECTS.md#optional-hardware-extension-ai-colour-detective) may be used as an extension or lab activity. A typical Arduino Uno/Nano-class microcontroller reads sensors and drives outputs; it should not be described as training a general machine-learning model unless a specific supported TinyML workflow is configured. The core six-month curriculum remains usable without electronics.
