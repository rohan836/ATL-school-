# Practical AI Learning Roadmap — Classes 5–9

**Programme:** 16 teaching weeks  
**Audience:** Classes 5–9, Batch C and Batch D  
**Status:** Proposed teaching plan; update the lesson log as lessons are actually delivered.  
**Purpose:** A practical starter pathway that helps students understand AI by coding, experimenting, training small models and building useful projects.

This roadmap supplements the [canonical eight-module AI curriculum](../AI-CURRICULUM-CLASSES-5-TO-9.md). It does not replace it. Topics are sequenced for a practical 16-week introduction. Exact calendar dates can be entered after matching the programme to the school calendar.

## The learning approach

Students should repeatedly:

**See it → Try it → Change it → Test it → Explain it → Build with it.**

Keep explanations short. Every major idea should connect to a visible experiment or a small product. Students should understand the work they build, not simply copy code or accept an AI-generated answer.

## 16-week curriculum

### Month 1 — Python, coding and AI foundations

| Week | Teach | Practical lesson / build | Students should be able to |
|---|---|---|---|
| 1 | What AI is; AI around us; AI vs ordinary rule-based programs; what AI can and cannot do | **AI Detective:** sort real-world examples, try a teacher-led AI demonstration and identify the problem it solves | Give simple examples of AI and explain what a chosen system does |
| 2 | Python setup; notebook cells; `print()`; variables; input; basic data types | **Number Guessing Game:** change a starter notebook so the computer gives clues and responds to the player | Run a notebook, change values and explain variables and input |
| 3 | Comparisons; `if/else`; loops; step-by-step algorithms | **Quiz Game and Pattern Generator:** build a small quiz or make the computer generate number patterns | Use conditions and loops to control a simple program |
| 4 | Functions; lists; importing a library; reading simple error messages | **Mini Python Toolkit:** create a calculator, list-based quiz or pattern tool using reusable functions | Explain a function, use a list and import a library |

### Month 2 — Data and machine learning

| Week | Teach | Practical lesson / build | Students should be able to |
|---|---|---|---|
| 5 | Jupyter Notebook workflow; code and Markdown cells; running cells; NumPy introduction; simple charts with Matplotlib | **Interactive Data Playground:** change numbers and see a chart update | Run cells in order, import a library and describe a simple chart |
| 6 | Rows, columns, datasets, labels, CSV files, missing or incorrect values; introductory pandas | **Data Detective:** explore a small, safe dataset such as plant counts, classroom objects or daily temperatures | Organise data, identify a problem in a dataset and describe a pattern |
| 7 | Machine learning; features and labels; training examples; regression and numeric prediction | **Number Predictor:** train a small model on a simple numeric dataset, make a prediction and compare it with the known value | Explain that a model learns a pattern from examples and produces an estimate |
| 8 | Classification; training vs test data; predictions; accuracy and common errors | **Handwritten Digit Recogniser:** use a prepared 0–9 digit dataset or approved demo, test new examples and inspect mistakes | Explain classification and why a model must be tested on examples it did not train on |

### Month 3 — Computer vision and generative AI

| Week | Teach | Practical lesson / build | Students should be able to |
|---|---|---|---|
| 9 | Images as pixels; colour channels; image classification; training examples | **Teach an Image Classifier:** classify safe object categories such as bottles, books or fruit using an approved tool or prepared dataset | Explain that images are represented as data and that labels guide classification |
| 10 | Object detection vs image classification; test conditions; model limitations | **Object Recognition Challenge:** change image backgrounds, angles, distance or lighting and record when the model fails | Distinguish classification from detection and describe conditions that affect results |
| 11 | Natural language processing; generative AI; large language models; prompting; hallucinations and verification | **AI Quiz or Study Assistant:** compare prompts, generate questions and check answers against teacher-approved sources | Write a clearer prompt and verify an AI-generated answer |
| 12 | AI coding assistants; asking for small changes; reading generated code; running, debugging and improving | **Build with an AI Assistant:** create a simple quiz, calculator or information app with teacher-guided help | Explain what the assistant contributed and describe how the code was tested |

### Month 4 — Applications and student projects

| Week | Teach | Practical lesson / build | Students should be able to |
|---|---|---|---|
| 13 | Connecting Python, a trained model and a simple application; responsible use in practice | **Model-powered Mini App:** show a model prediction in a simple notebook or interface; check data privacy, fairness and output reliability | Demonstrate a model in use and identify at least one limitation or risk |
| 14 | Finding a real problem; identifying users; choosing whether AI is useful; planning and dividing team roles | **Project Design Sprint:** choose a school or community problem and prepare a simple project plan | State the problem, intended user, proposed solution and how it will be tested |
| 15 | Building, testing, debugging, improving and documenting | **Project Build Lab:** make a working prototype, test different cases and improve one weakness | Show evidence of testing and explain one improvement |
| 16 | Demonstration, explanation, reflection and next steps | **AI Project Exhibition:** demonstrate the project and explain the problem, data, AI method, tests, failures and improvements | Present their work and explain what they understand rather than only showing the result |

## Class-wise expectations

Teach the same weekly theme across Classes 5–9, but adjust the amount of code, independence and explanation expected.

| Class | Expected level | Adaptation |
|---|---|---|
| 5 — Discover | Highly guided and visual | Use demonstrations, prepared notebooks, small code edits, object sorting and simple patterns. Keep typing and mathematics light. |
| 6 — Understand | Guided coding and data work | Write short Python programs, organise small datasets, label examples and run prepared model experiments. |
| 7 — Experiment | More independent coding and testing | Write and modify notebook cells, split examples into training and test sets, compare predictions and record errors. |
| 8 — Build | Applied Python and AI projects | Use functions and libraries, analyse datasets, train simple models and connect model outputs to a small application. |
| 9 — Create and evaluate | Greater independence and reasoning | Design experiments, compare model results, investigate errors, use AI coding assistants critically and document reproducible steps. |

Do not assume every student in a class has the same prior experience. Provide a starter version and an extension challenge for each activity.

## Project library to draw from

Choose projects according to class level, available devices and preparation time.

1. **Number pattern explorer:** generate sequences and ask students to predict the next value.
2. **Number predictor:** fit a simple regression model to a small, understandable dataset.
3. **Handwritten digit recogniser:** classify digits from 0 to 9 using a prepared dataset.
4. **Object image classifier:** classify safe, non-personal images such as fruit, stationery or recyclable objects.
5. **Object recognition experiment:** explore how position, lighting and background affect predictions.
6. **Data explorer:** turn a small dataset into charts and observations.
7. **AI quiz generator:** use a language model to draft questions, then verify and edit them.
8. **School information assistant:** create a simple guided chatbot using only approved, non-sensitive information.
9. **Waste awareness/classification tool:** demonstrate how image categories might support waste sorting; do not present it as a safety-critical sorting system.
10. **Student-designed application:** use Python and an AI coding assistant to prototype a solution to a real problem.

A project is successful when students can explain its purpose, inputs, method, output, tests and limitations. A polished appearance alone is not sufficient.

## Core skills to cover

- **Computational thinking:** decomposition, patterns, abstraction, algorithms and flowcharts.
- **Python:** output, variables, input, data types, conditions, loops, lists, functions, imports and debugging.
- **Notebook skills:** cells, execution order, Markdown notes, simple charts and recording experiments.
- **Data:** tables, CSV, labels, quality, missing values, training data and test data.
- **Machine learning:** regression, classification, prediction, training, testing and evaluation.
- **Computer vision:** pixels, image classification, object detection and model limitations.
- **Generative AI:** language models, prompts, generated content and verification.
- **AI-assisted development:** asking for small changes, understanding code, testing, debugging and iterating.
- **Project skills:** problem definition, teamwork, prototyping, evaluation and presentation.
- **Responsible AI:** privacy, bias, fairness, attribution and human checking, taught through project decisions rather than long standalone lectures.

## Suggested assessment

| Area | Weight |
|---|---:|
| Practical experiments and notebook work | 30% |
| Projects and prototypes | 30% |
| Understanding and explaining concepts | 20% |
| Problem-solving and creativity | 10% |
| Responsible use and teamwork | 10% |

Use a simple check after each lesson: Can the student explain what they tried, what happened and what they would change?
