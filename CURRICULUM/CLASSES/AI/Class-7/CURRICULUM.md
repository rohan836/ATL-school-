# Class 7 — AI & Computing Curriculum

**Duration:** 6 months · 12 sessions per month · 72 sessions total. **Core period:** 60 minutes per session; optional 15-minute extension. **Sections:** C and D share this curriculum; this is the single common copy.

## Course goal
Develop Python fluency, data handling, model-evaluation reasoning and critical AI literacy through evidence-based projects.

## Learning outcomes
- Write small Python programs using functions and data structures.\n- Clean and summarise simple datasets.\n- Explain classification/regression, test examples, baselines and generalisation.\n- Verify AI claims and present an evaluated project.

## Month-by-month project briefs

### Month 1 — Computing and algorithm design
**Concepts:** Decomposition, flowcharts, tracing, test cases and systematic debugging.

**Build:** Develop an algorithm, run traces, identify a failure and revise the steps. Explain why the change addresses the failure.

**Evidence:** project artefact, test record, explanation and one limitation. Use paper/offline alternatives where needed.

### Month 2 — Python fluency
**Concepts:** Types, conditions, loops, lists, dictionaries, functions and reusable code.

**Build:** Build a quiz, menu, task list or text analyser with functions and data structures. Test empty, expected and unexpected inputs.

**Evidence:** project artefact, test record, explanation and one limitation. Use paper/offline alternatives where needed.

### Month 3 — Data handling
**Concepts:** CSV-style tables, missing/duplicate values, summaries, simple statistics and charts.

**Build:** Clean a small non-sensitive dataset, create a chart and support a claim with evidence. Record the data source and limitations.

**Evidence:** project artefact, test record, explanation and one limitation. Use paper/offline alternatives where needed.

### Month 4 — Machine-learning workflow
**Concepts:** Features/labels, classification vs regression, test split, baseline and overfitting intuition.

**Build:** Compare a paper or teacher-guided model with a simple baseline. Keep test examples separate, record errors and discuss generalisation.

**Evidence:** project artefact, test record, explanation and one limitation. Use paper/offline alternatives where needed.

### Month 5 — Modern AI literacy
**Concepts:** Language-model prediction concept, prompt clarity, source checking, bias and privacy.

**Build:** Compare teacher-prepared responses, improve a prompt and check claims against approved source material. Mark unsupported statements.

**Evidence:** project artefact, test record, explanation and one limitation. Use paper/offline alternatives where needed.

### Month 6 — Evidence-based capstone
**Concepts:** Scope, prototype, test design, iteration, limitations and communication.

**Build:** Build a data visualisation, fictional classifier, quiz or source-grounded text helper. Include tests, one improvement and responsible-use review.

**Evidence:** project artefact, test record, explanation and one limitation. Use paper/offline alternatives where needed.

## Assessment and teacher guide

### Formative assessment
Use prediction questions, concept checks, code/algorithm tracing, test logs, observation and short exit tickets. Evaluate understanding—not speed, polish, device access or whether a model always gives a correct answer.

### Capstone rubric (20 points)
Score each category 0–4: problem/plan; understanding; build and individual contribution; testing and evidence-based improvement; responsible use and communication. A 0 means no evidence yet; 2 means developing with partial evidence; 4 means clear, accurate and independently justified evidence. Use the rubric formatively and adapt for accessibility.

### Minimum project evidence
- A clear problem and chosen approach.
- Program, notebook, physical artefact or explicitly labelled paper simulation.
- Test cases/results appropriate to the grade.
- One issue or limitation identified and one change made because of evidence.
- A short explanation of privacy, fairness or reliability, including where a person checks the result.
- Each learner explains their own contribution.

### 60-minute lesson rhythm
5 min retrieval/challenge · 10 min explanation/demo · 25 min build/investigation · 10 min testing/debugging · 10 min explanation/exit ticket. Adjust pace; do not skip testing or safety to finish a build. An optional 15-minute extension may support additional practice or stretch work.

### Differentiation
Support: starter templates, worked examples, fewer features, sentence frames, paired tracing. Core: build/modify, test multiple cases, record and fix an issue. Extension: compare approaches, add edge cases or justify a metric. Accept spoken, written, diagram-based and accessible demonstrations.

### Safety and responsible AI
Use school-approved tools and teacher-prepared, fictional, public or approved data. Never upload identifiable student names, faces, voices, locations, records or private work to public AI tools. Do not use models to classify real students by sensitive traits or make consequential decisions. Check factual claims against approved sources. No GPU, paid account, webcam, cloud service or public AI account is a prerequisite. Provide paper/offline alternatives. Keep any tool use transparent, permission-limited and under human supervision.

### Teacher preparation
Check devices, software, permissions and connectivity; prepare a known-good example and an offline alternative. Ask students to predict, test unusual inputs, record errors and explain changes. Follow school safeguarding, privacy, copyright and acceptable-use policies.

### Student reflection
What problem did we solve? How does it work? What did tests show? What failed or surprised us? What did we change and why? What should users not assume? What data/permissions need protection? Where must a person review the result?
