# Class 7 — Six-Month AI & Computing Curriculum

**Course:** Python, Data Skills and Applied AI Foundations  
**Duration:** 6 months · 12 sessions per month · 72 sessions total  
**Session length:** 60 minutes (optional extension to 75 minutes)  
**Level:** Foundation-to-intermediate; revisit key ideas briefly, then apply them.

## Course goal
Students build confidence writing small Python programs, organising and analysing data, and reasoning about how machine-learning models are trained and tested. They begin to evaluate generative AI rather than treating output as fact.

## Learning outcomes
Students can:
- Explain basic computer architecture, files, data representation, and responsible use.
- Translate a problem into an algorithm, use pseudocode/flowcharts, and debug systematically.
- Use Python variables, conditions, loops, lists, dictionaries, and functions for small tasks.
- Read CSV-style tables, clean simple inconsistencies, calculate summaries, and chart results.
- Explain features, labels, classification vs regression, train/test separation, generalisation, and model errors.
- Compare AI output using evidence, recognise bias and privacy risks, and verify important claims.
- Present a documented project with multiple test cases and a justified improvement.

## Six-month sequence

| Month | Focus | Essential concepts | Student evidence |
|---|---|---|---|
| 1 | Computing and algorithm design | Hardware/software recap, files, input-process-output, decomposition, flowcharts, tracing | Algorithm and debug log |
| 2 | Python fluency | Types, variables, conditions, loops, lists/dictionaries, functions, reusable code | Small multi-feature Python program |
| 3 | Data handling | CSV-like tables, cleaning missing/duplicate values, counts, mean/median where suitable, charts | Data notebook or script with a conclusion |
| 4 | Machine learning | Features/labels, classification vs regression, examples, separate test set, overfitting intuition, accuracy and error | Baseline model or paper experiment and evaluation |
| 5 | Modern AI literacy | Language-model pattern prediction, prompt clarity, source checking, bias, privacy, appropriate vs inappropriate tasks | Comparison of outputs with source-based fact check |
| 6 | Capstone engineering | Plan, prototype, test design, iteration, limitations, human oversight, presentation | Small working or clearly labelled simulated project |

## Technical expectations
Students should write most core Python themselves with scaffolds as needed. A notebook or simple local editor is appropriate. If an ML library is unavailable, use a transparent paper model or teacher-prepared demonstration. Do not let model output replace student reasoning. Avoid training large models, unbounded agents, or deploying projects on real people.

## Project pathway
Possible projects: student-created quiz analyser, school-garden data chart, fictional library-category classifier, simple survey explorer, or a fact-checking assistant grounded in a teacher-approved text. See [Project Guides](02-PROJECTS.md).

## Teaching and safety
Use short explain-build-test cycles, ask for predictions before execution, and require each team member to explain part of the program. Test unfamiliar examples and compare before/after changes. Use only approved data and tools. Never upload identifiable student data to public AI tools. Distinguish a language-model suggestion from a verified fact.

## Success standard
A strong result uses readable code, clean enough data, a fair test, a reasoned improvement, and an honest description of limitations.
