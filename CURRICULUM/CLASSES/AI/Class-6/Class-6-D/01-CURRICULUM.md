# Class 6 — Six-Month AI & Computing Curriculum

**Course:** Computing, Python and Introductory AI  
**Duration:** 6 months · 12 sessions per month · 72 sessions total  
**Session length:** 60 minutes (optional extension to 75 minutes)  
**Level:** Beginner-to-foundation; build on everyday computer use, not assumed coding skill.

## Course goal
Students move from using computers to explaining and building small programs. They learn core Python structures, represent simple data, and investigate how AI models use examples to make predictions.

## Learning outcomes
Students can:
- Explain input, processing, output, CPU/RAM/storage at an introductory level.
- Manage files and folders, identify common file types, and follow privacy/security basics.
- Express a task as an algorithm, use pseudocode/flowcharts, and debug a sequence.
- Write and modify Python using variables, basic types, conditions, loops, lists, and simple functions.
- Read a small table, count categories, make a basic chart, and interpret a result.
- Explain labels, features, classification, training/test examples, and why prediction errors matter.
- Use age-appropriate AI demonstrations critically, check claims, and propose a safe project.

## Six-month sequence

| Month | Focus | Essential concepts | Student evidence |
|---|---|---|---|
| 1 | Computer systems and digital practice | Input/output, CPU/RAM/storage, operating-system basics, files, folders, file types, safe accounts | System diagram and organised project files |
| 2 | Algorithms and problem solving | Decomposition, sequence, selection, repetition, pseudocode, flowcharts, tracing/debugging | Algorithm plus test cases |
| 3 | Python foundations | `print`, variables, strings/numbers/booleans, input, `if/else`, loops, lists | A small interactive program and code walkthrough |
| 4 | Data and visualisation | Rows/columns, categories, counts, simple charts, missing/inconsistent data | Cleaned mini-table and chart-backed conclusion |
| 5 | Machine-learning basics | Rule vs model, features/labels, training/test split by concept, classification, error, fairness | Card-based or teacher-guided classifier experiment |
| 6 | Build and evaluate | Problem choice, simple Python/data prototype, testing, iteration, AI safety and presentation | Tested capstone with a short report |

## Progression and boundaries
Introduce loops before asking students to build multi-step programs; use small datasets before charts or classification. Students may use a prepared notebook, offline editor, or teacher-controlled tool. Do not require cloud compute, paid tools, webcam data, or training a large model. Generation tools are optional demonstrations, not the course's technical foundation.

## Project pathway
Suggested projects include a quiz with conditions, a simple study timer or checklist, a survey-summary chart, or a paper/teacher-guided classifier using fictional data. See [Project Guides](02-PROJECTS.md).

## Teaching and safety
Demonstrate first, ask students to predict, let them modify one thing at a time, test normal and unusual inputs, and have them explain their reasoning. Use fictional or teacher-prepared data. Do not upload identifiable student information, photos, recordings, or school records to external AI services. Verify important claims against trusted sources and keep a human responsible for decisions.

## Success standard
Assess working logic, explanation, test evidence, iteration and responsible choices. A small program whose student can explain is stronger evidence than copied code they cannot describe.
