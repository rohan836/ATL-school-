## Project Assignment

| Project Assignment Section | Instructions / Information to Record |
|---|---|
| Project Title | First-Press Quiz Buzzer |
| Group Assignment | Group 3; this group works on this project. |
| Project Category | Interactive input and output |
| Difficulty Level | Beginner–Intermediate |
| Aim | Build a quiz board where the first team to press its button receives a visible or audible signal. |
| Project Problem / Introduction | Explain how quiz competitions need a fair way to identify the first team to answer. |
| Learning Objectives — What We Will Learn | Pushbutton inputs, open and closed circuits, output indicators, and the idea of first-press lockout. |
| Components Required | Two pushbuttons; LEDs; buzzer; resistors; breadboard; jumper wires; low-voltage supply; optional Arduino Uno for lockout and reset logic. |
| Component Description | Identify each component and write its purpose in the project. |
| Basic Concepts | Explain the electronics ideas used in this project: Pushbutton inputs, open and closed circuits, output indicators, and the idea of first-press lockout. |
| Working Principle | A button press changes an input state. The circuit/controller activates that team's indicator and, in the controller version, ignores the other button until reset. |
| Circuit / System Diagram | Draw and label the circuit or system diagram. Include power, ground, input, output, and component connections where applicable. |
| Construction Procedure | 1. Connect each team's button. 2. Add an LED or buzzer output. 3. Test each input. 4. Implement or demonstrate first-press behavior. 5. Add a reset control if the kit supports it. |
| Programming / Code | If a controller is used, attach or write the code and explain the main input and output steps. If no controller is used, write “Not required” and explain the circuit operation. |
| Testing Procedure | Press each button individually, then press both nearly together. Check whether the first-press rule and reset work. |
| Observation Record | Create a small observation record with columns for test/input, expected response, actual response, and notes. |
| Result / Expected Output | A two-team quiz buzzer demonstration. |
| Problems Faced | Record any difficulty encountered while assembling, programming, or testing the project. |
| Troubleshooting | Describe the checks or changes used to solve the problem. |
| What We Learned | Write 3–5 points about the concepts and practical skills learned. |
| Real-Life Applications | Identify one or two real-world uses or related examples. |
| Conclusion | Summarize what the group built, how it worked, and what was learned. |
| Future Improvement | Add a third team or a score counter. |
| Project Evidence | Add the labelled diagram and a teacher-approved photo or drawing of the model, if available. |
| Teacher Feedback | Space for teacher comments and suggestions. |

## Safety and Implementation Notes

- Use only low-voltage batteries or an approved current-limited lab supply. Never connect student projects to household mains.
- Use appropriate current-limiting resistors with LEDs. Disconnect power before changing connections.
- Ask the teacher to verify component ratings, transistor pinouts, and wiring before energizing a circuit.
- Use only kit-approved touch circuits and low-voltage components for the touch project.
- Conduct the water-level project with a plastic container, low-voltage probes, and direct teacher supervision. Keep power and controller boards away from spills; disconnect power before handling water. This is an educational model, not a safety alarm.
- Sound-activated demonstrations should be tested at reasonable sound levels and not use loud or startling sounds.
- Arduino/controller use is optional where specified; ensure the project can be taught with available components and teacher-approved alternatives.
- These prototypes are learning models, not certified real-world safety devices.
