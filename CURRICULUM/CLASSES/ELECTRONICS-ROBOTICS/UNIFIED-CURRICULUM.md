# Unified Electronics & Robotics Curriculum — Classes 5–9

**Purpose:** One shared curriculum framework for Classes 5–9. Teachers use the same topic sequence and lesson library, adapting the depth, independence, mathematics, coding, and project expectations to each class. Class C and D follow the same learning sequence; retain section-specific timetables and records separately.

## How to use this curriculum

1. Choose the unit and lesson that fits the school's timetable.
2. Teach the shared concept to the whole group.
3. Use the grade-level expectations below to differentiate the activity and assessment.
4. Check lab inventory and board/sensor specifications before selecting a build.
5. Assess students on safe practice, understanding, testing, explanation, and iteration—not only whether a project works.

This is a flexible sequence, not a fixed calendar. A practical planning baseline is 16–20 core lessons per cycle, with additional build and revision time where equipment or student readiness requires it.

## Shared learning sequence

| Unit | Shared topic | Suggested hands-on activity | Evidence of learning |
|---|---|---|---|
| 1 | Electronics in everyday life; inputs, processing, outputs | Identify the parts of everyday electronic systems | Label a system and explain its purpose |
| 2 | Lab safety, low voltage, component handling | Safety walk-through and safe/unsafe scenario sort | Follow lab rules and identify power limits |
| 3 | Electricity, conductors and insulators | Test approved materials in a simple circuit | Record observations and explain results |
| 4 | Open and closed circuits | Build a switch-controlled circuit | Draw and explain the circuit path |
| 5 | Power source, polarity, LEDs and resistors | Light an LED with a suitable current-limiting resistor | Identify polarity and explain the resistor's role |
| 6 | Switches and user controls | Build a simple controlled light or signal | Explain how the input changes the output |
| 7 | Series and parallel circuits | Build and compare low-voltage LED circuits | Compare observations and circuit layouts |
| 8 | Outputs: LEDs, buzzers and indicators | Make a light or sound indicator | Match an output to a defined purpose |
| 9 | Sensors as inputs | Explore an LDR, push button, or available sensor | Explain what is measured or detected |
| 10 | Thresholds and automatic responses | Build a light-triggered or distance-triggered response where parts allow | Describe the condition that activates the output |
| 11 | System diagrams and circuit diagrams | Draw a system block diagram and a circuit | Communicate a design before building |
| 12 | Controllers and basic programming (when hardware supports it) | Use simple sequence, condition, and loop logic | Explain or modify a short program |
| 13 | Actuators and motor safety | Demonstrate a suitable motor/servo using a compatible driver | Explain why a controller may not power a motor directly |
| 14 | Robotics: sensing and movement | Plan a robot response to an obstacle or line | Map sensor input to movement output |
| 15 | Capstone planning and constraints | Define a problem, sketch a design, list components | Provide a plan and success criteria |
| 16 | Build, test, and troubleshoot | Build a class-appropriate prototype | Use a checklist and test observations |
| 17 | Improve and retest | Change one design variable and compare results | Justify an improvement using evidence |
| 18 | Documentation and demonstration | Present circuit/system diagram, build, and findings | Explain design choices, limits, and next steps |

## Grade-level differentiation

| Class | Emphasis | Expected challenge | Example capstone |
|---|---|---|---|
| 5 | Discovery, component recognition, simple circuits, safety | Build with a guided diagram; identify power, path, input, and output | Switch-controlled light, buzzer alarm, or automatic light |
| 6 | Circuit comparisons, switches, sensors, systematic observation | Follow and adapt a diagram; record results; explain cause and effect | Sensor-triggered alarm or classroom indicator |
| 7 | Combining subsystems, simple logic, introductory controller use | Design a circuit from a block diagram; debug with a checklist; use simple conditional logic where supported | Smart-light prototype or sensor-based alert |
| 8 | Microcontroller inputs/outputs, structured code, calibration | Use variables, conditions, and loops where supported; test multiple conditions | Automatic plant/environment monitor or basic robot |
| 9 | System architecture, reliability, data, control, iterative engineering | Build and document an integrated system; collect repeatable test data; justify trade-offs | Line-following or obstacle-avoiding robot, if compatible hardware is available |

The table describes expected depth, not mandatory hardware. If the school does not have a compatible microcontroller, sensor, motor driver, or robot chassis, teach the concept with simulation, diagrams, paper prototypes, or a teacher demonstration instead.

## Assessment framework

Use the same assessment categories across classes, raising the expected independence and technical detail by grade:

- **Safety and care:** follows low-voltage rules, handles components correctly, leaves the lab organized.
- **Conceptual understanding:** explains the circuit/system and predicts what will happen.
- **Build and implementation:** constructs or simulates a solution using a diagram or plan.
- **Testing and troubleshooting:** tests systematically, records observations, and identifies likely faults.
- **Iteration:** makes a purposeful change and compares results.
- **Communication:** presents the design, evidence, limitations, and possible improvements.

Suggested evidence: short exit question, circuit sketch, observation table, practical checklist, and a brief project demonstration. Adapt scoring to the school's assessment policy.

## Safety and equipment rules

- Use only teacher-approved, low-voltage power sources for student activities.
- Never connect student-built circuits directly to mains electricity.
- Use an appropriate current-limiting resistor with LEDs and verify component ratings.
- Do not connect motors directly to microcontroller pins; use a compatible driver and suitable power source.
- Check the exact board, sensor, driver, battery, and connector specifications before publishing build instructions.
- Power down before changing wiring. Stop if a component becomes hot, smells unusual, or behaves unexpectedly.
- Provide a no-hardware alternative when parts are missing.
- Supervise cutting, soldering, batteries, and tools according to school policy.

## Teacher planning checklist

Before each unit, confirm: learning objective; class-level extension; components available; wiring/code reference for the exact hardware; safety briefing; fallback activity; assessment evidence; cleanup and storage plan.
